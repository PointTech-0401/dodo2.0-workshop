為什麼不設 max_output_tokens

兩種做法都有代價，正式 dodo 選了其中一邊，本專案跟進。

方案 A · PROMPT 指引

「一次最多兩個短句」

模型不保證逐字遵守，但句子一定是完整的。

方案 B · TOKEN 硬上限

長度守得住，但句子會被切在一半

講到第 47 個 token 就停，不管那句話說完了沒有。

max_output_tokens

正式 dodo 不設 max_output_tokens，本專案跟進：長度交給 Prompt 描述。

「停頓門檻」只在 server_vad 語音輸入有效，打字送出不會經過 VAD。

三種回合方式，三種取捨

右側 B 區的設定會組成 Realtime session.update。

SEMANTIC VAD

依語意判斷是否說完

較適合說話慢、句中會停頓的長者。

eagerness = low
SERVER VAD

依靜音時間切回合

容易直接觀察延遲與搶話的取捨。

silence_duration_ms = 800
PUSH TO TALK

按住錄音，放開才送出

停用 VAD，最容易在吵雜教室穩定操作。

（不使用 turn_detection）

barge-in 由 interrupt_response=true 與 Push-to-talk 的 response.cancel 負責，不是靠一句 Prompt 停止音訊。

開始前：連接真正的模型

未設定 Key 時聊天功能會明確停用；不會用固定句型假裝成模型回覆。

  • 第一次啟動時，在畫面內分別輸入 OpenAI API Key 與 OpenWeatherMap API Key。
  • 每個 Key 旁邊只有「測試」按鈕；實際儲存一律由畫面最下方那一個按鈕完成 —— 沒測試過的 Key 會在儲存時自動先測一次。
  • 也可以由講師預先在 .env 設定 OPENAI_API_KEY 與 WEATHER_API_KEY。
  • 天氣 Key 沒有設定時仍可進入 Workshop，但即時天氣工具會明確提示尚未設定。

preamble 是哪一段？

流程圖右下角那兩個 response，在畫面上長這樣。

DODO · PREAMBLE（工具前的開場）
我幫您看一下臺北現在的天氣。
DODO
臺北現在 26 度，有一點雲，出門帶件薄外套就好。
  • Realtime API 沒有 preamble 這種 item type。
  • 客端靠結構判斷：同一個 response 裡同時出現 message item 與 function_call item，那個 message 就是 preamble。
  • 工具結果送回去之後建立的下一個 response 才是正式回答。

把那句要求從「對話方式」刪掉再按「套用」，preamble 就會消失。

講師現場提醒

全班以「打字輸入／文字輸出」完成主線；輸入與輸出可獨立設定。

  • 鍵盤按「送出」會在同一個 session 建立文字回合，但不會使用 VAD 或靜音門檻。
  • A 區是模型 instructions，不設 token 上限；Prompt 不負責偵測使用者是否說完。
  • instructions 在建立連線時就隨 SDP offer 送出，按「套用」才會再 session.update。
  • 從語音輸入切成打字時，麥克風音軌會立即停止，不需等待儲存設定。
  • 語音連線失敗時會保留作品；可將輸入改成打字、輸出改成文字。
  • 查天氣或讀寫記憶前那一句「我幫您看一下」會標成 PREAMBLE。
