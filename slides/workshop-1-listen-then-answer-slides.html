API Key 與連線檢查

  • 第一次啟動時填入 OpenAI Key 與天氣 Key。

回答長度

控制長度有兩種做法。

做法 A · PROMPT 指引

「一次最多兩個短句」

句子完整，但模型不一定每次照做。

做法 B · 字數上限

長度固定

到上限就停止，句子可能斷在一半。

本專案不設字數上限，長度寫在 Prompt 裡。

「安靜多久算講完」只在使用麥克風時有作用，打字送出不經過這個判斷。

實作一：調整 Prompt

使用「打字輸入／文字輸出」，不需要耳麥。

  1. 1
    確認標題下方顯示「Realtime 已連線」。
  2. 2
    問「你叫什麼？我叫什麼？」，確認名字與稱呼。
  3. 3
    輸入：「我今天第一次自己搭公車去醫院，有點緊張。」
  4. 4
    修改「角色與身分」或「對話方式」，下方完整 Prompt 會同步更新。
  5. 5
    按「套用」，輸入同一句話。
  6. 6
    比較內容、語氣與長度。
  7. 7
    在「對話方式」修改長度規則，再比較一次。

工具前開場（Preamble）

對應流程圖右下角的兩次回覆。

DODO · PREAMBLE（工具前的開場）
我幫您看一下臺北現在的天氣。
DODO
臺北現在 26 度，有一點雲，出門帶件薄外套就好。
  • Realtime 的事件裡沒有標示開場白的欄位。
  • 同一次回覆裡同時有文字與工具呼叫，那段文字就是開場白。
  • 工具結果送回後的下一次回覆，才是正式回答。

操作：問「臺北今天天氣如何？」；刪掉「對話方式」裡要求先講一句的那一行，套用後再問一次。

Prompt 的限制

示範：同一份 Prompt、同一句話。

  1. 1
    在「對話方式」最後加一句「一次最多兩個短句」，按「套用」。
  2. 2
    同一句話連問五次：「今天天氣好冷，你覺得我要穿什麼？」
  3. 3
    數五次裡有幾次只講兩句。
對照

插話中斷

由回合偵測執行，不需要模型配合。長度規則寫在 Prompt 裡，模型不一定每次照做。

需要確定發生的行為寫在程式裡。第二堂的主動規則就是這樣設計。
