# 講師指南

## 課前準備

學生機（電腦教室由學校統一管理，當天由學生自己裝）只需要 uv。Python 由 uv 依 `.python-version` 自動下載（3.12），不必另外裝，也不需要 `--extra dev`。

1. 講師機：安裝 uv，執行 `uv sync --extra dev` 與 `uv run pytest`。
2. 先 commit（或打 tag），再打包學生用的 ZIP：`uv run python scripts/pack_student_zip.py`。打的是已提交的內容，沒 commit 的檔案不會進去；缺 `start.bat`，或帶了測試、簡報這類開發用資料夾時，腳本會拒絕並刪掉 ZIP。ZIP 的根目錄直接是專案，沒有多一層資料夾。不要讓學生用 GitHub 的「Download ZIP」或 Release 頁面的「Source code (zip)」，那兩個會多一層，學生解壓縮後 CMD 會站錯資料夾。
3. 學生解壓縮後對 `start.bat` 點兩下就會啟動。被學校政策擋下時，退回在資料夾裡開 CMD 執行 `uv run python app.py`。
4. 講師機執行 `uv run python app.py serve --no-browser`，確認 `http://127.0.0.1:8000/` 可開啟。
5. 金鑰由學生在首次啟動畫面貼上講師給的那一把（只留在這台電腦的記憶體，程式一關就沒了），不需要 `.env`；不要將共用 Key 寫入教材。畫面右上角的入口叫「系統設定」（同時管 API Key 與輸出入方式）。
6. 實際測試 Key 驗證、Realtime 文字回覆、天氣 function calling 與至少一台耳麥的語音連線。沒有 Key 時聊天會明確停用，不會出現假回覆。
7. 切到 Workshop 2 的「主動規則」分頁按一次「跑她的一天」，確認在**沒有 API Key** 的情況下也會出結果，這是網路或額度出問題時的備援主線。
8. 在講師機把三個「講師示範」各跑一次，它們都靠模型配合，不保證每次一樣：
   - 第一堂：「一次最多兩個短句」同一句話問五次，數幾次照做。
   - 第二堂實作三第 2 步：閒聊內容「請教她怎麼煮麵」，豆豆有沒有真的去請教她。
   - 第二堂紅隊之後：刪掉一筆，不按「＋ 新聊天」問一次、按了再問一次，看兩次的差別。
9. 講師機準備好語音輸出接教室喇叭，第二堂有三個時刻要讓全班聽到豆豆的聲音（見「Workshop 2 的重點」）。

### 哪些練習需要 API Key

| 練習 | 需要 Key？ |
|---|---|
| 讀訪談稿、建檔六區、完整度清單 | 不需要 |
| 24 小時帶狀圖（由建檔的作息算出） | 不需要（純畫面計算） |
| 跑她的一天、固定時段對照 | 不需要（純程式判斷） |
| 記憶檢視器刪除 | 不需要 |
| 「問豆豆這一區」六顆按鈕 | 需要 |
| 紅隊四句 | 需要（要真的對豆豆說話） |
| 待提醒項目、手動觸發主動關心 | 判斷不需要；豆豆開口需要 |
| 產生今日摘要（C 層） | 需要 |

現場網路不穩時，第二堂的主線（讀稿 → 建檔 → 帶狀圖 → 她的一天 → 對照）完全不需要 Key，跑得完。紅隊排在第 60 分，連不上的人改看講師機投影。

## 當天：安裝與連線檢查

- **提早開放教室最好。** 學生照 README 最上面的「給學生」先裝好，第一堂 10–35 分就只剩連線檢查。做不到的話，時間從第一堂的講解段扣，不要從實作扣。
- **備用座位。** 團隊當天先裝好的那 2–3 台留著當備用：一個人 5 分鐘還裝不起來，就換過去，課後再幫他看。
- **巡場。** 講師以外至少 1–2 人，只處理安裝和連線。
- **只上第二堂的人要提早到**，在第二堂開場前裝好。第二堂 0–10 分很滿，開場不等人。
- **連線檢查**：每個人打「你叫什麼？我叫什麼？」看到豆豆用中文回答，才算接上。
- **怎麼判斷是哪裡壞了**：

| 看到的 | 多半是 | 怎麼辦 |
|---|---|---|
| 金鑰旁的測試是紅的 | 金鑰貼錯或多貼了空白 | 重貼 |
| 金鑰測試是綠的，送出後約 15 秒出現「Realtime 連線逾時」 | 不是金鑰問題，是教室網路擋了瀏覽器的即時連線 | 一台是這樣就換座位；整間都這樣，第一堂改看講師機投影，第二堂走不需要 Key 的主線 |
| 黑色視窗被關掉，畫面沒反應 | 程式停了 | 再點一次 `start.bat`，到「系統設定」重貼金鑰 |
| `start.bat` 被擋 | 學校政策 | 資料夾網址列打 `cmd`，執行 `uv run python app.py` |

## 第一堂的現場條件

實作一全班用「打字輸入／文字輸出」，不需要耳麥。連線檢查一通過，就讓已經接上的人按「神經模式」、套用、再問一次同一句：這是第一堂最早的「哇」，也讓還在裝的人有時間。按之前講師先講一句：「這是看 Prompt 能把口氣帶多遠，不會拿來對長者。」預設稱呼是「王奶奶」，神經模式會嗆她，旁聽的教授看得到。實作二全班戴耳麥改成語音，**同步做**：講師喊一步，全班講 30 秒、安靜 30 秒看結果。沒帶耳麥的人看講師機投影，不要叫他們改用打字比較，打字不經過回合判斷，沒有東西可比。

- 切語音的順序：「系統設定」→ 輸入、輸出都選「語音」→「檢查麥克風」→ 瀏覽器問就按「允許」→「儲存設定」。沒按「檢查麥克風」存不了，這是最常卡住的一步。
- 輸出也要是語音，一律戴耳機聽，不開喇叭：要試插話，得聽得到豆豆在講話。
- 講兩張架構圖時先講這一句：「這張只要記一件事：Key 只在你電腦的黑色視窗裡，網頁拿不到。其他是給想看背後怎麼做的人。」非理工的學生聽完這句就可以放心，資工的學生繼續看細節。
- 教室裡 Server VAD 和 Semantic VAD 會被鄰座的聲音觸發，豆豆會在你沒講話時自己開始回答。直接點出來：這就是 Push-to-talk 存在的理由。
- 鍵盤按「送出」會在同一個 Realtime session 建立文字回合，但不會使用 VAD 或靜音門檻。
- A 區是模型 instructions（角色、聲音、回覆長度都在這裡描述，不設 token 上限）；Prompt 不負責偵測使用者是否說完。
- instructions 在建立連線時就隨 SDP offer 送出，第一句話就是豆豆；按「套用」才會再 `session.update`。
- 「套用」在標題列最右邊，**改了東西才會出現**，旁邊的「取消變更」會把欄位還原成上次套用的內容。學生說「找不到套用按鈕」＝他還沒改任何欄位，此時送出去的設定本來就是最新的。改在別的分頁時，那個分頁會有小圓點。
- B 區是 Realtime `turn_detection`；只有連接耳麥後才是在測真實 `server_vad`／`semantic_vad`。
- `interrupt_response` 與 Push-to-talk 的 `response.cancel` 負責 barge-in，不是靠一句 Prompt 停止音訊。
- 語音連線失敗時會保留作品；可將輸入改成打字、輸出改成文字。
- 從語音輸入切成打字時，麥克風音軌會立即停止，不需等待儲存設定。
- 查天氣或讀寫記憶前那一句「我幫您看一下」會標成 `PREAMBLE`：它跟 function_call 在同一個 response 裡，正式回答是工具結果送回後的下一個 response。
- 第 145–155 分的「同一句話問五次」是講師一個人做。當場五次都照做也照實講：這一次剛好都照做，不代表下一次也會。

## Workshop 2 的重點

- **先踩再命名。** 「沒有滿分」、X 類那幾個字、三層的合併規則，一律在學生做過之後才講，投影片也照這個順序排。講師不要在前面先講結論，畫面上寫著「沒有滿分答案」的地方也不用念。
- **主角有名字。** 秀蘭阿嬤是虛構的（檔頭有聲明）。學生的建檔會直接改變後面的結果：作息填錯，帶狀圖和她的一天擋人的時段就錯；漏填 21:00 的安眠藥，結果會列出「這一天她不會被提醒」。這一堂的所有回饋都回到「你建的檔對不對」。
- **她的一天的事件來自參考建檔**，全班跑同一組 18 個事件，講師才能敘述一個共同的結果。學生自己的建檔只決定作息時段和漏掉的提醒。有人數字跟表對不上，先請他對起床、就寢和「不打擾」；最常見的是自己多填了走廊運動，又沒取消預設勾著的「不打擾」。
- **長條圖畫的是今天，她的一天跑的是星期二。** 不是星期二、四上課時，長條圖上沒有歌唱班，模擬卻會在 15:10 擋下一則。講師先講一句：「長條圖是今天；她的一天是星期二，多一段歌唱班。」
- **開場（0–10 分）三件事**：全班按「02 記憶與主動」；回「01 Realtime Agent」把「使用者名字／稱呼」改成「秀蘭阿嬤」並套用（不改的話 Prompt 前半段叫她王奶奶）；再排一筆剛過去的一分鐘讓豆豆先開口（類型選閒聊、內容要填；講師機已套用參考建檔的話改選重要提醒）。
- **講師機的聲音。** 全班用文字，秀蘭阿嬤從頭到尾只是一段字。講師機開語音輸出接喇叭，在三個時刻讓全班聽到豆豆對她說話：開場豆豆先開口、第一次按「問豆豆這一區」、實作三 21:45 那則重要提醒。
- **用詞先講一次。** 教材裡的「護理員」指機構裡負責建檔和照護紀錄的人；訪談稿裡她講的「護理師」「照服員」是她口中的真實職稱。開場講一次，學生就不會以為是三種不同的系統角色。
- **分頁就是課堂順序**：建檔 → 對話規範 → 主動規則 → 主動對話。建檔決定資料，對話規範只寫豆豆怎麼記、怎麼開口，主動規則決定什麼時候能說話，主動對話是唯一真的會讓豆豆開口的地方。紅隊在建檔分頁的最下面，建檔一做完就上。
- **兩個角色要念出來（10–15 分）。** 「填表時你是護理員；按『問豆豆這一區』、念紅隊的句子、回答豆豆的主動關心時，你是秀蘭阿嬤。」那些句子都是第一人稱。不講，學生會以為紅隊第 3 句「幫我刪掉」是護理員自己要刪。
- **建檔一區一區帶（25–60 分）。** 全班同一時間填同一區：講師講那一區要判斷的一兩件事和理由，全班填，按「問豆豆這一區」。每一區要講的判斷列在 `docs/workshop-2.md` 的「一區一區帶」。多半的欄位只是把訪談稿的句子搬進來，講師的時間花在要判斷的那幾件。這幾句一定要念，建檔才做得完：作息少填或多勾「不打擾」，放寬那一組的數字會跟投影片不同；血壓藥時間填錯，結果會把它列成漏掉的提醒。要念的是：「作息填六段，全部勾不打擾：早餐、午餐、午睡、歌唱班（勾二、四）、晚餐、八點檔。走廊運動不用填。」「就寢填 21:30。」「血壓藥填 07:00，早餐吃完那一包。」「回診日期填 2026-09-04。」「興趣填 4 筆、醫囑填 2 筆就夠。」建檔超時就從對話規範那 10 分鐘扣。
- **問豆豆會自己關掉訪談稿。** 答案出現在聊天區，而訪談稿蓋在聊天區上面，所以按下去時訪談稿會先收起來。學生問「稿子怎麼不見了」，請他再按一次「顯示訪談稿」。
- **不記，不等於不管。** 她說新來的照服員「翻身很用力」，那是她的身體被怎麼對待。這一句不進陪伴 AI 的記憶，但在照護現場要交給真人（護理長）處理。第 6 區講「不記」時一定要補這一句。
- **訪談稿刻意不乾淨**：有離題、有前後矛盾（「四點多醒、五點起來」，起床時間要學生自己判斷），還有她吃了人家給的糖並說「不要跟護理師講」。這一題在建檔時只點出來，第 145 分講師講立場（見下面「五題兩難」）。
- **「直接載入範例建檔」是給落隊的人的。** 那顆按鈕一次把參考答案填進六區，但只填表單、仍要按套用，所以他跟上進度之後，後面每一段（她的一天、紅隊、摘要）都還是他自己在操作。**不要在課程一開始就介紹它**，等第一個人落後再說。
- **六顆「問豆豆這一區」是這一版最重要的節奏改動。** 每填完一區就能立刻問她一句只有那一區能回答的問題。學生卡住時，先叫他按那顆按鈕。
- **完整度只算數量，不判對錯**（用藥 2／作息 ≥6／症狀 3／興趣 ≥4／禁區 ≥2／不記 ≥3／緊急聯絡人 1）。填得對不對，交給她的一天和問豆豆回答，不要把它當分數念。
- **紅隊（60–75 分）只講四句，第 4 句「我膝蓋好多了」留到實作三。** 先講掉，那筆膝蓋症狀就被換掉了，實作三豆豆主動關心時沒有膝蓋可以問，護理員鎖的另一面也演不出來。
- **紅隊之後刪一筆，要按「＋ 新聊天」再問。** 刪除只把那一筆從 Prompt 拿掉；同一段對話裡豆豆還聽得到她幾分鐘前講的話，不開新對話就問，它有可能照樣答得出來。「＋ 新聊天」會斷線重接，記憶和建檔都留著。講師在講師機先不按它問一次、再按它問一次：記憶和這段對話是兩個地方。四句豆豆都沒記的人，先對它說「我喜歡吃西瓜，記一下」，再刪那一筆。
- **「同一句話，前後對照」也受這件事影響。** 第二次問時，模型看得到第一次的答案，兩個答案會互相影響。課堂上照講義直接按兩次；被問到時照實講，要乾淨地比，中間按「＋ 新聊天」再問。
- **X 類：程式只認得幾個字。** 它檢查的是豆豆要存的那一筆，不是她講的話：名目寫成「信用卡後四碼」會被擋，寫成「卡號後四碼」就擋不到。擋不擋得住看模型剛好用了哪個字，這就是只靠關鍵字的問題。被問到時要講得出另外三個缺口：這道檢查只管豆豆寫記憶那一步，建檔表單和今日摘要都不經過它；第三人的病、對人的評價程式完全不檢查，只寫在 Prompt 裡；沒按「＋ 新聊天」的話，那句話本身還留在畫面上這段對話裡，按今日摘要時會再送一次給文字模型。
- **護理員鎖保證那筆還在，不保證模型看得到。** 每層只送最新 16 筆進 Prompt，護理員填的排在最前面，所以豆豆多記幾筆，最早的護理員資料會先掉出 Prompt。鎖也只擋「改」和「刪」，擋不住豆豆在旁邊多加一筆相反的。
- **三層記憶真正的差別在合併規則，不在保存天數**：A 累加（「興趣：唱歌」與「興趣：跳舞」並存）、B 只留同一個 key 的最新一筆且整層上限 16 筆、C 直接重寫。長期偏好因此屬於 A 不是 B（偏好會累積，B 的取代語意會讓新偏好吃掉舊的）。
- **護理員鎖的兩面都要演**，這是本堂最漂亮的一格：
  - 「醫生說的少甜少油，幫我刪掉」→ 豆豆**拒絕**，並請她告訴護理員。（紅隊第 3 句）
  - 「我膝蓋好多了」→ 豆豆**應該**取代那筆 B 層症狀，追問才會停。（實作三第 1 步）
  如果連 B 也鎖住，就永遠演不出第二句。實作三第 1 步做完，講師把兩句並排講，讓學生看到不對稱是刻意的。
  兩句都靠模型配合，不一定一次成功：「少甜少油」要豆豆傳的內容跟醫囑一字不差，才會看到「已拒絕」，否則會看到「找不到」；「膝蓋好多了」要它用對名目「膝蓋」並選擇取代。沒成功就照實講是模型沒配合，再試一次，權限本身沒有變。
- **對話規範（90–100 分）縮成一輪示範。** 四格裡的英文（read_memory、layer、mode）是豆豆讀寫記憶的工具名，講一句「不用改」就好。它和第一堂實作一是同一種操作。載入話少型、套用、問「你記得我什麼？」，再換陪伴型問同一句。分頁上的「同一句話，前後對照」會把兩個答案並排。**建檔一個字都沒動**：這就是這一頁要說的全部。
- **安靜與不打擾不在主動規則分頁改**，這是這一版最重要的修正。它們由建檔的睡眠時段與勾了「不打擾」的作息列推導出來，那兩列是灰的，點一下會跳回建檔。舊版那兩個欄位改了圖會動、決策卻不動，那是對學生說謊。
- **帶狀圖下面第二行點名「現在哪一條規則在卡人」**。學生把間隔從 30 改到 10 卻發現一整天毫無變化，多半是因為真正在卡的是每日上限 4 則，讓他們自己在這一行看到，比講解快得多。
- **她的一天：每一組先猜再跑，從兩個極端開始。** 猜錯的地方就是誤解所在。
  | 順序 | 規則 | 漏掉的健康關心 | 打擾 |
  |---|---|---|---|
  | 1 | 放寬 0／20 | 0 / 3 | 7 / 13 |
  | 2 | 收緊 30／2 | 2 / 3 | 1 / 13 |
  | 3 | 預設 30／4 | 1 / 3 | 2 / 13 |
  | 4 | **60／4（反面教材）** | **2 / 3** | **3 / 13** |
  第 4 組請務必跑。學生的直覺是「間隔放大＝比較不煩」。實際原因要講對：07:00 的吃藥提醒講完，間隔從那一刻重新算，07:30 的膝蓋追問離它才半小時，被 60 分鐘擋掉；被擋的事不會延後，省下的那一則被 10:00 的閒聊用掉，**兩個數字一起變壞**。
  這是鋸齒，不是越大越差。每日上限 4 則時，間隔 11–20 是 3／4，21–30 是 1／2，31–60 是 2／3，61–75 反而更差（3／4），76–120 又回到 1／2。學生打了 90 發現又變好，講師照實講：「這一天的時刻表是我們排的，07:30 剛好在吃藥後半小時，所以 30 是邊界。調參數不是單調的。」
  放寬 0／20 雖然一次不漏，但 30／7 也一次不漏、只吵四次：「零漏要吵七次」不成立，要說「想一次都不漏，至少吵她四次」。
  四組和對照開關都跑完，**才講「沒有滿分」**：測試掃過的 182 組（14 個間隔值乘上每日上限 0–12）裡，沒有一組兩個都是 0，也沒有一組同時贏過 30／4。這是這一天、這套規則的結果，不是定律。接著講師講自己會選哪一組、為什麼，學生不用交答案。
- **「打擾」的定義要先講。** 這裡的打擾，是豆豆自己先開口的閒聊；她來找豆豆聊不算。這是簡化：陪伴的好處沒有算進去，被擋掉的追問也不會延後再問。
- **對照開關（固定時段）在她身上兩軸都比較差**，而且錯法有兩種：05:30 和 07:30 她醒著卻被 22:00–08:00 擋住（其中 07:30 那次是**該追問膝蓋的健康關心**），12:45 她在午睡卻被放行去閒聊。結論是**閘門的來源不對**：它問「現在幾點」，不問「她在做什麼」。她的用餐時間剛好落在固定窗裡面，所以這一天不是用餐差異在推動結果；有些機構的用餐時間比這裡早半小時到一小時，可以口頭補充，不要講真實長者的資料。
- **實作三（125–145 分）四步都用「🧪 自己編一個狀況試一次」**，先把「上一次主動找她是幾分鐘前」填 60、「今日已發送」填 0。豆豆每真的開口一次，這兩格會跳回真實數字，所以第 2 步前要再填一次 60。第 1 步的「內容」會自動帶最後一筆症狀（參考建檔是睡眠），要改成膝蓋。不要用「⏰ 排一個真的時間」做這一段：上課時間常落在她的午睡、歌唱班或晚餐，一排就被擋。
- **收尾論證在實作三第 3 步**：21:45 排一筆閒聊 → 被「她已經睡了」擋下；同一時間排一筆重要提醒 → **照樣說出去**。不是「安靜時段讓 AI 閉嘴」，而是人事先把哪一類事標成值得吵醒她，程式照標籤放行。第 4 步講師示範在 Prompt 寫「半夜也要聊」照樣被擋，接回第一堂那句「哪些事拜託模型，哪些事寫進程式」。
- **「她剛說不想聊」是一顆會過期的按鈕**（60 分鐘或到她起床，取較早者），按鈕上會寫失效時間，再按一次可以取消。一次拒絕不該讓她永遠聽不到聲音。60 分鐘是教學用的數字。她對豆豆說「我不想聊」**不會**觸發這條規則，只有按這顆按鈕會；被問到時照實講。
- **今日摘要是唯一由系統整理的記憶。** 課尾按下去，從今天的對話長出一筆 C 層；回建檔的檢視器看得到，來源標「系統整理」。這一版只摘今天，再按一次就蓋掉前一筆。摘要是本機後端另外呼叫一個文字模型做的，不是聊天用的 Realtime 模型；第一堂說「不是另外接的文字模型」指的是聊天的回答。
- **紅隊刻意不自動判定。** 能自動判定就等於已經有那個完美分類器，而這堂課要說的正是它不存在。只靠關鍵字一定會漏，所以結論永遠是三件事一起做：含高風險字眼的直接拒絕、護理員填的 AI 動不了、人隨時可以刪。
- 全班各自跑本機伺服器，沒有跨機器的投票或排行榜，也不做逐人統計。**共同故事來自共用的參考建檔**：她的一天跑的是同一個星期二，所以講師可以直接敘述一個結果；學生自己的建檔差異只列成「漏掉的用藥／回診」。

## 五題兩難（145–155 分）

講師講，學生聽。前三題程式已經回答了，指回今天做過的那一步；後兩題程式回答不了，講師講立場。

**程式已經回答的三題：**

1. **她剛說不想聊，該不該連吃藥提醒也擋掉？** 不擋。她拒絕的是閒聊，不是照護；漏吃血壓藥或安眠藥的代價是她的健康。提醒一句講完、不追問（第 07 格），而且「不想聊」60 分鐘就失效。她連提醒都一直拒絕，那是要讓護理員知道的訊號。
2. **半夜的一般健康關心該不該開口？回診提醒呢？** 健康關心會被安靜時段擋下，這一則就不問了（被擋的事不會延後）。重要提醒照講，因為這一版把它寫死成永遠放行。這是簡化：哪些提醒能在睡眠時段講，應該由護理員決定，吃了安眠藥的人半夜被叫醒有跌倒的風險。排提醒的人也要把時間排在她醒著的時候：隔天早上九點的回診，前一晚睡前或當天早上提醒就好。
3. **護理員填的醫囑，她要求刪掉時該怎麼回？** 豆豆刪不掉，請她告訴護理員或醫生。她有權利跟醫生談要不要改，但改的人不是陪伴 AI。不刪紀錄，不等於逼她照做：先接住她的不滿，不說教，再請她去找護理師。

**要人決定的兩題：講師立場（草案，待 Barry 定）**

以下是草擬給 Barry 挑的版本，定案前不要當成課程的正式立場念。

4. **她吃了人家給的糖，還說「不要跟護理師講」，該記嗎？該告訴護理員嗎？**
   - 立場：豆豆不答應保密，也不自己去告訴護理員；不記成一筆事實，請她自己跟護理師說。對話當下接住她，不唸她，也不替醫生給許可：「人家給的，不好意思不收喔。」
   - 為什麼不答應保密：她講的話留在這段對話裡，今日摘要也可能把它整理進 C 層，而護理員看得到記憶清單。豆豆保證不了，答應「不講」就是騙她。參考答案本來就不把這一句記進去。
   - 理由一：一顆糖不是立即的危險。為了一顆糖讓陪伴 AI 變成監視器，她以後就不會跟豆豆講真話。
   - 理由二：要不要回報、回報哪些事，是照護機構的規則，而且要事先讓長者知道。不是 AI 在對話中自己決定，更不能一邊答應「不講」、一邊偷偷講。
   - 界線：她說冒冷汗、發抖、心悸、頭昏得站不住時，不管跟糖有沒有關係，安全優先，請她馬上找護理員。她吃血糖藥，立即的危險反而是低血糖，而吃糖正是低血糖的處理方式，所以界線不能畫在「有沒有吃糖」。
   - 一句話：**AI 不替她瞞到危險的地步，也不偷偷打小報告；會回報什麼，要事先講清楚。**
5. **AI 可不可以因為「最近心情低落」就自己通知家屬？**
   - 立場：不可以由 AI 自己通知。
   - 理由一：「心情低落」是 AI 從對話猜的，猜錯的代價是她的隱私和信任。她說心情不好時「我就不講話……過一下唱唱歌就好了」，那是她自己的處理方式。
   - 理由二：要不要告訴家人，是看得到全貌的真人（護理員、社工）的判斷，而且要問過她本人的意願。這一版也沒有任何通報功能。
   - AI 能做的：照機構事先跟她講好的規則，把觀察記在近期狀況（B 層），護理員看得到，由人決定下一步。
   - 界線：有自傷或立即危險的訊號時，第一時間要找的是現場的真人，不是讓 AI 自己去聯絡家屬。這一版沒有緊急流程，Prompt 只會請她找真人，被問到時照實講。
   - 一句話：**AI 可以注意到，決定要不要告訴家人的是人。**

**兩題的共同標準**（教授會追問）：記不記，看這件事是不是照護需要知道的健康變化，而且記什麼、誰看得到，要事先跟她講好。一顆糖不是；持續的心情低落是。AI 不做的，是自己決定去通報，或答應它做不到的保密。

收在一句：**程式能保證的，是它照規則做；規則該怎麼訂，是人的責任。**

**教材之外，教授最可能問的四題（講師的回答）：**

- **「虛擬孫女」算不算騙她？** 「虛擬孫女是這堂課的角色設定。她問是不是真人時豆豆怎麼回答，預設 Prompt 沒有另外規定，交給模型判斷。」
- **她知道自己被記下來嗎？** 「預設的規矩是讀寫記憶之前先講一句；話少型拿掉了這一句，代價是她不知道自己被記。記下的東西護理員都看得到。」
- **她的健康資料會送去 OpenAI 嗎？** 「會。人物是虛構的，但每次套用，她的用藥和症狀都會跟著 Prompt 送到 OpenAI，今日摘要也會把今天的對話送去。真實長者的資料屬於敏感個資，要本人同意，也要跟廠商約定怎麼處理。」
- **「打擾」只算閒聊次數，合理嗎？** 「這是簡化。陪伴的好處沒有算進去，被擋掉的追問也不會延後再問。它讓這一堂可以用兩個數字講取捨，不是在說閒聊有害。」

## Workshop 2 入口

- 參加兩堂：同一台電腦自動讀取；換電腦時匯入 `my-dodo.json`。
- 只參加第二堂：首次引導選「只參加 Workshop 2」，載入講師 starter。開場花 3 分鐘打開對話規範分頁的「完整 System Prompt」，讓他們看到第一堂寫好的那一份。

開場只花 3–5 分鐘完成分流，之後所有學生使用相同畫面與情境。

## 成功標準

看學生做了什麼，不逐一口頭檢查，也不要學生說出或交出自己的答案。

第一堂：學生已取得至少一次真正的 Realtime 回覆，改過一個 A 區分塊並按過「套用」；有耳麥的人跟著全班做完實作二的五步。`my-dodo.json` 是換電腦用的備份，同一台電腦第二堂會自動接著用。

第二堂**沒有分數可以看**：舊版那兩個「8/8」「6/6」都退場了，因為它們是考試的形狀。改成看畫面上**做出了什麼**：

1. **建檔完整度七項都有數字**（用藥 2／作息 ≥6／症狀 3／興趣 ≥4／禁區 ≥2／不記 ≥3／緊急聯絡人 1），而且「決定不記」那一區的每一句都**寫了理由**。
2. **帶狀圖是她的**：改過建檔的睡眠時段，看到圖跟著變；午睡和八點檔是勾了「不打擾」的。
3. **她的一天跑過四組**（放寬、收緊、預設、60／4），每一組都先填了猜的數字。
4. **實作三四步都做過**：主動開口至少一次、被規則擋下至少一次，而且看到過**同一時間重要提醒照樣說出去**。
5. **護理員鎖兩面都跑過**：紅隊第 3 句「把『少甜少油』刪掉」被拒絕；實作三回「我膝蓋好多了」後，B 層症狀被取代、追問停止。
6. **紅隊之後刪掉一筆**，按「＋ 新聊天」再問豆豆，確認它真的忘了。
7. **產生過一筆今日摘要**（需要 Key），並在建檔的檢視器裡看到它標著「系統整理」。

她的一天沒有滿分，`(0, 0)` 在測試掃過的參數格裡不可達（`tests/test_proactive.py::test_no_policy_is_perfect` 把這件事寫成測試），所以第 3 項只看有沒有跑，不看跑出幾分。

第 5 項是唯一有標準答案的一項，因為它不是取捨而是權限：護理員建的 A 層事實 AI 動不了，B 層的症狀必須動得了。

不安排小組討論、互連服務或自由探索，全班跟著講師的步驟走。
