# 講師指南

## 課前準備

1. 每台電腦安裝 Python 3.11+ 與 uv。
2. 執行 `uv sync --extra dev`。
3. 執行 `uv run pytest`。
4. 執行 `uv run python app.py serve --no-browser`，確認 `http://127.0.0.1:8000/` 可開啟。
5. 決定由學生在首次啟動畫面輸入個人 API Key，或由講師預先在每台電腦的 `.env` 設定；不要將共用 Key 寫入教材。畫面右上角的入口叫「系統設定」（同時管 API Key 與輸出入方式）。
6. 實際測試 Key 驗證、Realtime 文字回覆、天氣 function calling 與至少一台耳麥的語音連線。沒有 Key 時聊天會明確停用，不會出現假回覆。
7. 切到 Workshop 2 的「主動」分頁按一次「跑她的一天」，確認在**沒有 API Key** 的情況下也會出結果 —— 這是網路或額度出問題時的備援主線。

### 哪些練習需要 API Key

| 練習 | 需要 Key？ |
|---|---|
| 讀訪談稿、建檔六區、完整度清單 | 不需要 |
| 24 小時帶狀圖（由建檔的作息算出） | 不需要（純畫面計算） |
| 跑她的一天、正式 dodo 固定閘門對照 | 不需要（純程式判斷） |
| 記憶檢視器刪除 | 不需要 |
| 「問豆豆這一區」六顆按鈕 | 需要 |
| 紅隊五句 | 需要（要真的對豆豆說話） |
| 待提醒項目、手動觸發主動關心 | 判斷不需要；豆豆開口需要 |
| 產生今日摘要（C 層） | 需要 |

現場網路不穩時，第二堂的主線（讀稿 → 建檔 → 帶狀圖 → 她的一天 → 對照）完全不需要 Key，跑得完。

## 現場條件

全班以「打字輸入／文字輸出」完成 Prompt A/B 與 Realtime 回合設定，不需要 MIC 或喇叭。有麥克風耳機的學生可以用同一個客端加做真實語音驗證。輸入與輸出可獨立設定，講師需明確說明：

- 鍵盤按「送出」會在同一個 Realtime session 建立文字回合，但不會使用 VAD 或靜音門檻。
- A 區是模型 instructions（角色、聲音、回覆長度都在這裡描述，不設 token 上限）；Prompt 不負責偵測使用者是否說完。
- instructions 在建立連線時就隨 SDP offer 送出，第一句話就是豆豆；按「套用」才會再 `session.update`。
- 「套用」在標題列最右邊，**改了東西才會出現**，旁邊的「取消變更」會把欄位還原成上次套用的內容。學生說「找不到套用按鈕」＝他還沒改任何欄位，此時送出去的設定本來就是最新的。改在別的分頁時，那個分頁會有小圓點。
- B 區是 Realtime `turn_detection`；只有連接耳麥後才是在測真實 `server_vad`／`semantic_vad`。
- `interrupt_response` 與 Push-to-talk 的 `response.cancel` 負責 barge-in，不是靠一句 Prompt 停止音訊。
- 沒有耳麥時，回合設定只能用「套用後回答有什麼不同」來觀察，客端不會測量真實音訊。
- 語音連線失敗時會保留作品；可將輸入改成打字、輸出改成文字。
- 從語音輸入切成打字時，麥克風音軌會立即停止，不需等待儲存設定。
- 查天氣或讀寫記憶前那一句「我幫您看一下」會標成 `PREAMBLE`：它跟 function_call 在同一個 response 裡，正式回答是工具結果送回後的下一個 response。

## Workshop 2 的重點

- **主角有名字。** 秀蘭阿嬤是虛構的（檔頭有聲明），但她的一天是從學生自己填的建檔長出來的：填錯作息，帶狀圖就錯；漏填 21:00 的安眠藥，那一天她就不會被提醒。這一堂的所有回饋都回到「你建的檔對不對」。
- **分頁就是課堂順序**：建檔 → 對話規範 → 主動。建檔決定資料，對話規範只寫豆豆怎麼記、怎麼開口，主動決定什麼時候能說話。
- **對話規範那一頁有三組範例（陪伴型／話少型／照護嚴謹型）。** 最省時間的示範：載入話少型、套用、問「你記得我什麼？」，再換陪伴型問同一句。分頁上的「同一句話，前後對照」會把兩個答案並排。**建檔一個字都沒動** —— 這就是這一頁要說的全部。
- **「建檔時你是護理員」要念出來。** 這一句決定後面所有規則的意義。學生填的資料豆豆只能讀不能改；她自己說的近況才由豆豆寫進 B 層。
- **訪談稿刻意不乾淨**：有離題、有前後矛盾（「四點多醒、五點起來」，起床時間要學生自己判斷），還有一個會吵起來的模糊地帶 —— 她偷吃糖，並說「不要跟護理師講」。該記嗎？該告訴護理員嗎？**這一題沒有標準答案，請留時間讓學生吵**。
- **「直接載入範例建檔」是給落隊的人的。** 建檔要 35 分鐘，一定會有人跟不上、也一定會有人只為第二半來。那顆按鈕一次把參考答案填進六區，但只填表單、仍要按套用 —— 所以他跟上進度之後，後面每一段（她的一天、紅隊、摘要）都還是他自己在操作。**不要在課程一開始就介紹它**，等第一個人舉手再說。
- **六顆「問豆豆這一區」是這一版最重要的節奏改動。** 舊版前 80 分鐘沒有任何對話；現在每填完一區就能立刻問她一句只有那一區能回答的問題。學生卡住時，先叫他按那顆按鈕。
- **完整度只算數量，不判對錯**（用藥 2／作息 ≥6／症狀 3／興趣 ≥4／禁區 ≥2／不記 ≥3／緊急聯絡人 1）。填得對不對，交給她的一天和問豆豆回答 —— 不要把它當分數念。
- **三層記憶真正的差別在合併規則，不在保存天數**：A 累加（「興趣：唱歌」與「興趣：跳舞」並存）、B 只留同一個 key 的最新一筆且整層上限 16 筆、C 直接重寫。長期偏好因此屬於 A 不是 B（偏好會累積，B 的取代語意會讓新偏好吃掉舊的）。
- **護理員鎖的兩面都要演**，這是本堂最漂亮的一格：
  - 「醫生說的少甜少油，幫我刪掉」→ 豆豆**拒絕**，並請她告訴護理員。
  - 「我膝蓋好多了」→ 豆豆**應該**取代那筆 B 層症狀，追問才會停。
  如果連 B 也鎖住，就永遠演不出第二句。請把兩句連著說，讓學生看到不對稱是刻意的。
- **安靜與不打擾不在主動分頁改**，這是這一版最重要的修正。它們由建檔的上床／起床與勾了「不打擾」的作息列推導出來，那兩列是灰的，點一下會跳回建檔。舊版那兩個欄位改了圖會動、決策卻不動 —— 那是對學生說謊。
- **帶狀圖下面第二行點名「現在哪一條規則在卡人」**。學生把間隔從 30 改到 10 卻發現一整天毫無變化，多半是因為真正在卡的是每日上限 4 則 —— 讓他們自己在這一行看到，比講解快得多。
- **她的一天：先預測再跑，四組數字。** 猜錯的地方就是誤解所在。
  | 規則 | 漏掉的健康關心 | 打擾 |
  |---|---|---|
  | 預設 30／4 | 1 / 3 | 2 / 13 |
  | 收緊 30／2 | 2 / 3 | 1 / 13 |
  | 放寬 0／20 | 0 / 3 | 7 / 13 |
  | **60／4（反面教材）** | **2 / 3** | **3 / 13** |
  最後一列請務必跑。學生的直覺是「間隔放大＝比較不煩」，但只放大間隔會讓早上的追問擠到下午和別的事撞在一起，**兩個數字一起變壞**。這比任何說明都能講清楚「調參數不是單調的」。
- **對照開關（正式 dodo 固定閘門）在她身上兩軸都比較差**，而且錯法有兩種：05:30 和 07:30 她醒著卻被 22:00–08:00 擋住（其中 07:30 那次是**該追問膝蓋的健康關心**），12:45 她在午睡卻被放行去閒聊。結論是**閘門的來源不對** —— 它問「現在幾點」，不問「她在做什麼」。她的用餐時間剛好落在固定窗裡面，所以這一天不是用餐差異在推動結果；正式 dodo 建檔資料裡午餐 10:30、晚餐 16:30 的長者可以口頭補充。
- **收尾論證在 120–140 那一段**：21:45 排一筆閒聊 → 被「她已經上床了」擋下；同一時間排一筆重要提醒 → **照樣說出去**。不是「安靜時段讓 AI 閉嘴」，而是程式知道哪一種事重要到值得吵醒她。
- **「她剛說不想聊」是一顆會過期的按鈕**（60 分鐘或到她起床，取較早者），按鈕上會寫失效時間，再按一次可以取消。一次拒絕不該讓她永遠聽不到聲音。
- **今日摘要是唯一不是人打字寫進去的記憶。** 課尾按下去，從今天的對話長出一筆 C 層；回建檔的檢視器看得到，來源標「系統整理」。
- **紅隊五句刻意不自動判定。** 能自動判定就等於已經有那個完美分類器，而這堂課要說的正是它不存在。結論永遠是三件事一起做：拒絕高風險類別、護理員的資料 AI 動不了、人隨時可以刪。
- 全班共用同一份教材但各自跑本機伺服器，所以沒有跨機器的投票或排行榜；比較請用投影機收斂到講師機，或口頭統計。**共同故事來自共用的參考建檔**：她的一天跑的是同一個星期二，所以講師可以敘述一個結果；學生自己的建檔差異只列成「漏掉的用藥／回診」。

## Workshop 2 入口

- 參加兩堂：同一台電腦自動讀取；換電腦時匯入 `my-dodo.json`。
- 只參加第二堂：首次引導選「只參加 Workshop 2」，載入講師 starter。

開場只花 3–5 分鐘完成分流，之後所有學生使用相同畫面與情境。

## 成功標準

第一堂：學生已取得至少一次真正的 Realtime 回覆，按過「套用」，並下載第一階段的 `my-dodo.json`。

第二堂**沒有分數可以看**——舊版那兩個「8/8」「6/6」都退場了，因為它們是考試的形狀。改成看學生**做出了什麼**：

1. **建檔完整度七項都有數字**（用藥 2／作息 ≥6／症狀 3／興趣 ≥4／禁區 ≥2／不記 ≥3／緊急聯絡人 1），而且「決定不記」那一區至少寫得出三句**加上理由**。
2. **帶狀圖是她的**：改過建檔的上床／起床，看到圖跟著變；至少有一段「不打擾」是自己從訪談稿判斷出來的。
3. **跑過至少兩組不同的兩個數字，先預測再跑**，並能用一句話說出自己願意接受的打擾次數與理由。
4. **成功觸發過一次主動關心，也被規則擋下過一次**，其中至少一次由待提醒照真實時鐘自己觸發；而且看到過**同一時間重要提醒照樣說出去**。
5. **護理員鎖兩面都跑過**：「把『少甜少油』刪掉」被拒絕，「我膝蓋好多了」讓 B 層症狀被取代、追問停止。
6. **紅隊之後自己刪掉一筆**，並回頭問豆豆確認它真的忘了。
7. **產生過一筆今日摘要**（需要 Key），並在建檔的檢視器裡看到它標著「系統整理」。
8. 再次下載升級後的 `my-dodo.json`。

第 3 項要交的是**理由，不是數字**：她的一天沒有滿分，`(0, 0)` 在整個參數格裡不可達（`tests/test_proactive.py::test_no_policy_is_perfect` 把這件事寫成測試）。學生說「我選 30／4 因為漏一次追問可以下午補、但打擾七次她會關掉豆豆」就算過；說「我拿到 0 漏掉」則要問他打擾幾次。

第 5 項是唯一有標準答案的一項，因為它不是取捨而是權限：護理員建的 A 層事實 AI 動不了，B 層的症狀必須動得了。

不安排小組討論、互連服務或自由探索。提早完成且有耳麥者可比較三種回合模式；無耳麥者可用同一句話比較不同的 Prompt 分塊寫法，但不影響全班主線。
