# 講師指南

## 課前準備

1. 每台電腦安裝 Python 3.11+ 與 uv。
2. 執行 `uv sync --extra dev`。
3. 執行 `uv run pytest`。
4. 執行 `uv run python app.py serve --no-browser`，確認 `http://127.0.0.1:8000/` 可開啟。
5. 決定由學生在首次啟動畫面輸入個人 API Key，或由講師預先在每台電腦的 `.env` 設定；不要將共用 Key 寫入教材。畫面右上角的入口叫「系統設定」（同時管 API Key 與輸出入方式）。
6. 實際測試 Key 驗證、Realtime 文字回覆、天氣 function calling 與至少一台耳麥的語音連線。沒有 Key 時聊天會明確停用，不會出現假回覆。
7. 切到 Workshop 2 按一次「執行 6 個情境」與「跑一整天」，確認兩者在**沒有 API Key** 的情況下也會出結果 —— 這是網路或額度出問題時的備援主線。

### 哪些練習需要 API Key

| 練習 | 需要 Key？ |
|---|---|
| 8 題記憶分類（含寫入記憶）、記憶檢視器刪除 | 不需要 |
| 主動規則的 24 小時帶狀圖 | 不需要（純畫面計算） |
| 執行 6 個情境、跑一整天 | 不需要（純程式判斷） |
| 紅隊挑戰四句話 | 需要（要真的對豆豆說話） |
| 待提醒項目、手動觸發主動關心 | 判斷不需要；豆豆開口需要 |

現場網路不穩時，第二堂仍可用不需要 Key 的四項撐完主線。

## 現場條件

全班以「打字輸入／文字輸出」完成 Prompt A/B 與 Realtime 回合設定，不需要 MIC 或喇叭。有麥克風耳機的學生可以用同一個客端加做真實語音驗證。輸入與輸出可獨立設定，講師需明確說明：

- 鍵盤按「送出」會在同一個 Realtime session 建立文字回合，但不會使用 VAD 或靜音門檻。
- A 區是模型 instructions（角色、聲音、回覆長度都在這裡描述，不設 token 上限）；Prompt 不負責偵測使用者是否說完。
- instructions 在建立連線時就隨 SDP offer 送出，第一句話就是豆豆；按「套用」才會再 `session.update`。
- 「套用」在標題列最右邊，**改了東西才會出現**，旁邊的「取消變更」會把欄位還原成上次套用的內容。學生說「找不到套用按鈕」＝他還沒改任何欄位，此時送出去的設定本來就是最新的。改在別的分頁時，那個分頁會有小圓點。
- B 區是 Realtime `turn_detection`；只有連接耳麥後才是在測真實 `server_vad`／`semantic_vad`。
- `interrupt_response` 與 Push-to-talk 的 `response.cancel` 負責 barge-in，不是靠一句 Prompt 停止音訊。
- 沒有耳麥時，回合設定只能用「套用後回答有什麼不同」來觀察，客端不會測量真實音訊。
- 語音連線失敗時會保留作品；可將輸入改成打字、輸出改成文字。
- 從語音輸入切成打字時，麥克風音軌會立即停止，不需等待儲存設定。
- 查天氣或讀寫記憶前那一句「我幫您看一下」會標成 `PREAMBLE`：它跟 function_call 在同一個 response 裡，正式回答是工具結果送回後的下一個 response。

## Workshop 2 的重點

- 第二堂有自己的兩個 Prompt 分塊（記憶使用規則、主動關心規則），加上三段由長者資料、`workspace.memory` 與主動規則自動生成的段落。合併後的 instructions 可以在「完整 System Prompt（Workshop 1 + 2）」裡完整檢視，按第二堂的「套用」才 `session.update`。
- 記憶分類**會真的寫入**：答對的 A／B／C 卡直接進「豆豆現在記得什麼」並同步到 session，X 卡答對則什麼都不寫。按第二次不會產生重複資料，所以可以放心讓學生反覆修改。卡片裡的稱呼跟著「長者稱呼」欄位走。
- 三層記憶真正的差別在**合併規則**，不在保存天數：A 累加（「興趣：唱歌」與「興趣：跳舞」並存）、B 只留同一個 key 的最新一筆且整層上限 8 筆、C 直接重寫。**長期偏好因此屬於 A 不是 B**（偏好會累積，B 的取代語意會讓新偏好吃掉舊的），記憶卡第 5 題答案是 A。
- 最好的示範是連著說四句：「我喜歡吃鳳梨」→「我喜歡吃西瓜」→「我喜歡吃芭樂」→「我不喜歡吃西瓜」。前三句並存（舊版本到這裡只剩芭樂），第四句應該讓豆豆用 `mode="remove"` 只移掉西瓜那一筆。如果它忘記用 remove、改成新增「不喜歡的食物：西瓜」，畫面上就會出現兩筆矛盾記錄 —— **停在這一格討論：AI 寫得進去不代表收得回來，所以「人可以刪」不是備案。**
- 實作二有四層：七列規則表加 24 小時帶狀圖（純畫面）、6 個固定情境驗證規則（純程式）、「跑一整天」看規則的累積代價、`觸發主動`分頁讓豆豆真的先開口。決策全部走同一個 `choose_event`；請務必強調「程式決定說不說、模型決定怎麼說」。
- 帶狀圖下面那一行會點名**現在是哪一條規則在卡人**。學生把冷卻從 30 改到 10 卻發現一整天毫無變化，多半是因為真正在卡的是每日上限 4 則 —— 讓他們自己在這一行看到，比講解快得多。
- `觸發主動`分頁是一條線：先填「這次要處理的事件」，再用切換器選時鐘 —— `⏰ 排到真實時間` 跑**真實時鐘**（每 5 秒對一次，時間到自己觸發、每筆只觸發一次、可刪除），`🧪 假設狀態試打一次` 的四個欄位全是**假設值**，每一欄都寫著它要打贏主動規則的哪個數字。兩邊說出去的訊息記進同一份累積量；待提醒清單在切換器下面，兩個模式都看得到。
- 現場示範建議：先在待提醒排一筆「剛過去的那一分鐘」，讓它自己跳出來；再用手動測試比較 15:30 的 reminder → 通過；同一件事改成 23:30 → 被安靜時段擋住；改成 emergency → 照樣開口。
- 「跑一整天」是本堂唯一沒有正確答案的練習，請刻意不要給答案。流程：先讓學生**預測**預設規則會漏幾件、打擾幾次，再跑；然後改成 21–09／60 分／3 則再跑（早上八點的血壓藥會被擋掉，這一格請停下來討論）；最後放寬到全天無限制（打擾 8 次）。收尾時要求每個人用一句話說出自己願意接受的打擾次數與理由。
- 記憶檢視器的「刪除」是本堂的安全收尾：紅隊挑戰讓學生把不該記的東西寫進去，再由他們自己刪掉，並回頭問豆豆確認它忘了。關鍵字過濾一定會漏（「後四碼」就繞過了），所以結論永遠是三件事一起做，不是靠一個過濾器。
- 全班共用同一份教材但各自跑本機伺服器，所以沒有跨機器的投票或排行榜；比較請用投影機收斂到講師機，或口頭統計。

## Workshop 2 入口

- 參加兩堂：同一台電腦自動讀取；換電腦時匯入 `my-dodo.json`。
- 只參加第二堂：首次引導選「只參加 Workshop 2」，載入講師 starter。

開場只花 3–5 分鐘完成分流，之後所有學生使用相同畫面與情境。

## 成功標準

第一堂：學生已取得至少一次真正的 Realtime 回覆，按過「套用」，並下載第一階段的 `my-dodo.json`。

第二堂：記憶分類顯示 `8/8` 且下方記憶檢視器真的長出資料、主動情境顯示 `6/6`，至少成功觸發過一次主動關心並被安靜時段擋下一次（其中一次用待提醒項目自動觸發），跑過至少兩組不同規則的「一整天」並能說出自己選的取捨，學生再次下載升級後作品。

注意「跑一整天」不列入通過標準 —— 它沒有滿分。要求學生交出的是理由，不是分數。

不安排小組討論、互連服務或自由探索。提早完成且有耳麥者可比較三種回合模式；無耳麥者可用同一句話比較不同的 Prompt 分塊寫法，但不影響全班主線。
