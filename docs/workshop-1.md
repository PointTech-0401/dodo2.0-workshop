# Workshop 1：讓 Dodo 聽完，再回答

主題：把一個會講話的 AI 拆成三件事：講什麼、什麼時候換人講、一次講多長

時間：165 分鐘

## 這堂課真正要教什麼

會講話的 AI 不是「Prompt 多寫幾句」就會變自然。學生要分清楚三件事，每一件在這個專案裡都找得到位置：

| 這一層管什麼 | 白話說 | 在畫面上的哪裡 |
|---|---|---|
| Model instructions（Prompt） | 豆豆是誰、講話什麼口氣、能講什麼不能講什麼 | 右邊 A 區那五個分塊 |
| Turn detection（回合控制） | 什麼時候開始聽、怎麼判斷你講完了、你插話算不算數 | 右邊 B 區 |
| Output length（長度） | 一次回答多長 | A 區的「對話方式」分塊 |

**「最多講兩句」只能用寫的，不能用鎖的。** Prompt 裡可以叫豆豆講短一點，但模型不保證每次都照做。那為什麼不設字數上限？因為上限一到就硬切，句子會斷在一半。所以這個專案不設字數上限：長度用 Prompt 描述，不用程式砍。

**「安靜多久算講完」只有用麥克風講話時才有意義。** 打字按送出不會經過這一關。

**Prompt 是什麼時候送出去的？** 一連上線就跟著送出去，所以豆豆的第一句話就已經是你設定的角色；按「套用」會再送一次更新。若不在連線時送、只靠事後補送，第一個回合可能落在 OpenAI 的預設人格上；我們真的遇過模型因此用英文回答。

## 學習成果

- 講得出 Prompt、VAD（自動判斷你講完了沒）、Push-to-talk 各自負責什麼，以及為什麼長度交給 Prompt，而不是設硬上限。
- 用真正的 OpenAI Realtime API，比較改了不同分塊之後回答有什麼不一樣。
- 分清楚聲線（音色）和「個性與聲音」分塊（演法）：同一句話換演法、換聲線，聽出兩者各管什麼。
- 比較三種「怎麼判斷你講完了」的方式：Server VAD、Semantic VAD、Push-to-talk。
- 按「套用」把設定真的送進正在進行的對話，再用同一句話比前後差別。
- 分清楚哪些事寫在 Prompt 裡拜託模型，哪些事交給程式。這一句接到第二堂。

## 開始前：安裝與連線檢查（10–35 分）

安裝前先放架構圖，只講一句：Key 只在這台電腦的 Terminal 裡，網頁拿不到。接著貼金鑰時大家就知道 Key 去了哪裡。

安裝步驟寫在 `README.md` 最上面的「給學生」，投影片也有一張「安裝」：裝 uv、打開白板上的短網址下載並解壓縮、對 `start-w1.bat` 點兩下、在第一次的畫面貼金鑰。`start-w1.bat` 開的是第一堂的畫面，只看得到「01 Realtime Agent」。

**連線檢查**：每個人在聊天區打「你叫什麼？我叫什麼？」按送出，看到豆豆用中文答出名字和稱呼，才算接上。這一步同時證明三件事：程式有跑起來、金鑰有效、這台電腦連得到 OpenAI 的即時服務。

**接著馬上玩一次**（已經接上的人先做，等還在裝的人）：按 A 區「人格版本」的「神經模式」，按「套用」，再問一次「你叫什麼？我叫什麼？」。同一個模型、同一句話，口氣完全變了，這是本堂第一個「哇」。按之前講師先講一句：「這是看 Prompt 能把口氣帶多遠，不會拿來對長者。」做完按「溫柔陪伴」、套用，換回預設再進講解。

### 金鑰怎麼填

第一次啟動時，畫面上會分別要你填 OpenAI 的 Key 和天氣的 Key。每個 Key 旁邊只有一顆「測試」，這顆按鈕只確認這把 Key 有沒有效；真正存下來靠畫面最下面那顆按鈕。沒測過的 Key 會在存之前自動測一次。兩把 Key 是一起跑的，不用等一把測完再測另一把。測過之後又改了 Key，那行字會退回去，剛才那個 ✓ 也跟著不見。

設定完之後，右上角「系統設定」還可以再打開；視窗右上角有「×」（按 Esc 也行），關掉會丟掉還沒存的東西。

Key 只送到這台電腦上的程式裡，跟著程式一起活著，程式一關就沒了；不會存進瀏覽器、不會寫進你下載的作品檔、也不會出現在網頁程式裡。Terminal 被關掉之後，要到「系統設定」再貼一次。天氣 Key 沒填一樣可以上課，只是問天氣時豆豆會明講「還沒設定」。

沒填 OpenAI Key 時聊天會直接停用，不會拿罐頭句子假裝自己是模型。

## 實作一：Prompt 只改變「豆豆怎麼回答」

1. 選「打字輸入／文字輸出」，確認標題下面寫著「Realtime 已連線」（沒連上會寫「尚未連接 Realtime」）。
2. 先問「你叫什麼？我叫什麼？」，確認 Prompt 裡的名字和稱呼生效了。
3. 用預設的 Prompt，輸入：「我今天第一次自己搭公車去醫院，有點緊張。」
4. 也可以先按「人格版本」的三個系統預設（溫柔陪伴／神經模式／啦啦隊長）聽差別。這三個預設會換掉 5 個分塊和聲線，但你取的名字和稱呼會留著。你改過任何一格，就會自動記成第四個「自訂」；換去試系統預設之後，按「自訂」就能拿回自己的版本。
5. 挑一個分塊改。打字／文字模式下看得出差別的是「角色與身分」和「對話方式」（例如追問的規矩）；「個性與聲音」管的是講多快、聲音高低，要到實作二戴耳機、用語音才聽得出來。改的同時，下面那份完整 Prompt 會馬上跟著變。
6. 按標題列右邊的「套用」，再輸入**一模一樣**的那句話。那顆按鈕只有在你改過、而且還沒送出時才會出現。看不到這顆按鈕，就代表模型收到的已經是畫面上這一份。下面那份完整 Prompt 只能看不能改，要改就回上面的分塊。
7. 比較內容、口氣和長度。**不要**把打字回答的快慢當成 VAD 的效果，那是兩回事。
8. 在「對話方式」分塊裡改長度規則（例如「一次最多兩個短句」對比「可以講長一點」），再比一次回答長度，這是用寫的請豆豆配合，不是程式硬砍。
9. 問「臺北今天天氣如何？」，看聊天區出現 `PREAMBLE` 那一句；把「對話方式」裡要求先講一句的那一行刪掉、套用、再問一次，那一句就不見了（見下面「那句『我幫您看一下』是什麼？」）。

預設的 Prompt 是虛擬孫女、臺灣繁體中文、講話慢一點、溫暖一點；其中「查東西之前先講一句」是為了教學加的（見下面）。預設聲線是 `sage`。

**那句「我幫您看一下」是什麼？** 預設的「對話方式」分塊要求豆豆在查天氣之前，先講一句說明自己要做什麼，例如「我幫您看一下臺北現在的天氣」。這句在畫面上標成 `DODO · PREAMBLE（工具前的開場）`，用虛線框起來，跟正式回答分開。

實作一的最後一步就用這個：全班問「臺北今天天氣如何？」看這句開場出現；再把那句要求從「對話方式」刪掉、按「套用」、問同一句，那句開場就不見了。

> **實作備註（給維護的人）**：Realtime API 沒有 preamble 這種東西，客端是靠結構認出來的：同一個 `response` 裡同時出現 message 和 function_call，那個 message 就是 preamble；工具結果送回去之後建立的下一個 `response` 才是正式回答。

**還有一種開場，不是你要求的。** 有時候豆豆沒有要查任何東西，卻先把心裡的盤算講出來，例如「我想一下怎麼陪你聊這個」。這叫旁白，畫面上標成 `DODO · 旁白（模型把心裡話講出來了）`，杏色虛線框。課堂上不一定看得到，模型不講就不會有，那不是壞掉。

兩種標籤差在哪：`PREAMBLE` 是你自己在分塊裡要求的，把那句要求刪掉就會消失；旁白沒有人要求，是模型自己的習慣。這裡兩種都留在畫面上，看得到才講得清楚。

> **實作備註（給維護的人）**：判斷不是比對字串，是讀模型自己標在 output item 上的 `phase`，`commentary` 就是旁白。用關鍵字猜會連豆豆正常講故事時的「我想想」一起抓進來，所以只認這個標籤，沒有標的就不動那顆泡泡。同一個 `response` 裡有 function_call 時，那一輪仍然走 preamble。

## 實作二：聲音導演（105–125 分）

用打字問、戴耳機聽。這一段不開麥克風，五十個人同時做也不會互相干擾。

開始前：右上角「系統設定」→ 輸入維持「打字」、輸出選「語音」→ 按「儲存設定」。沒有用到麥克風，不用按「檢查麥克風」。

1. 輸入「講一個 30 秒的睡前故事給我聽。」先聽預設的「溫柔陪伴」怎麼講。
2. 只改「個性與聲音」分塊，換成下表其中一種演法，按「套用」。
3. 輸入**一模一樣**的那句話，聽語氣、速度、停頓差在哪。聲音還是同一個人。
4. 分塊不動，只換「Dodo 的聲線」（例如 `ash` 或 `ballad`），按「套用」。畫面會自己重新連線，再問同一句：這次換了一個人的聲音，演法還在。
5. 演法和聲線自己搭一組。改過任何一格，系統就記成「自訂」，下課可以下載帶走。

| 演法 | 貼進「個性與聲音」的寫法 |
|---|---|
| 悄悄話 | 用氣音、很小聲地講，像怕吵醒旁邊的人。 |
| 夜市叫賣 | 像夜市喊價的老闆，大聲、很有精神，尾音拉長。 |
| 深夜電台 DJ | 低沉、慢，每句話中間停一下。 |
| 廟口講古 | 抑揚頓挫，講到關鍵處故意停住。 |

**聲線和 Prompt 是兩件事。** A 區的「Dodo 的聲線」決定音色（10 種可以挑），「個性與聲音」分塊決定用字、節奏和態度。改分塊不會換成另一個人的聲音；改聲線也不會讓豆豆變得比較有耐心。程式不會偷偷從你寫的形容詞裡去猜語速。

**豆豆用聲音回答過之後，同一段對話就不能換聲音**，這是 OpenAI 的規定。改了聲線按「套用」，畫面會自己斷線重接；重接之後是一段新的對話，剛才講過的話豆豆就不記得了。講師可以拿這件事說明：一個 API 的限制，會直接變成使用者看得到的行為。

**演不出來也是教材。** 寫在「個性與聲音」裡的演法是拜託，模型不一定每次都演到位。課前在講師機把四種各試一次，挑效果最明顯的兩種先示範；當場沒演出來就照實講，最後一段「Prompt 是拜託，不是保證」會再看到同一件事。

沒帶耳機的人看投影、聽講師機的喇叭。

## 實作三：真正的回合控制（125–145 分）

右邊 B 區改的東西，會直接送進正在進行的那段對話：

- **Semantic VAD（等待傾向 low）**：聽你話的意思判斷你講完了沒。適合講話慢、句子中間會停頓的人。
- **Server VAD（安靜 800 毫秒）**：你安靜夠久就算講完。最容易直接看出「反應快」和「被搶話」之間的拉扯。
- **Push-to-talk**：完全不猜，按著講、放開才送出。吵雜教室裡最穩，所以選語音輸入時先用這個；B 區的預設仍是 Semantic VAD，只有改成語音輸入的那一刻會切過來。
- **你一開口就讓豆豆停下來**：你插話時中斷豆豆正在講的那句。Push-to-talk 模式下靠取消目前這一輪做到。

打字送出不經過回合判斷，所以這一段只能用講的做。

### 全班同步，講師喊一步

50 個人各做各的，教室會同時有幾十個人在講話，誰也聽不出自己的結果。所以全班做同一步：

- **講 30 秒，安靜 30 秒。** 講師說「講」，全班照投影片上那句話講；講師說「停」，全班安靜，看自己的逐字稿和豆豆的反應。
- **一律戴耳機聽，不開喇叭。** 輸出也要是語音：要試插話，得聽得到豆豆在講話。開喇叭的話，鄰座聽得到，麥克風也會收到豆豆自己的聲音。
- **沒帶耳麥的人看投影。** 講師在講師機上同步做每一步。不要叫他們改用打字比較，打字沒有經過這一關，沒有東西可比。

開始前：右上角「系統設定」→ 輸入也改成「語音」（輸出在實作二已經是語音）→ 按「檢查麥克風」，瀏覽器問就按「允許」→ 按「儲存設定」。沒按「檢查麥克風」存不了。畫面會自己重新連線。

| 步 | B 區設定（改完按「套用」） | 全班一起講 | 看什麼 |
|---|---|---|---|
| 1 | 改成 Semantic VAD，等待傾向 low（選語音輸入時 B 區會先變成 Push-to-talk） | 「我今天早上去……（停一秒）……市場買了一把青菜。」 | 豆豆等你講完才回答 |
| 2 | Server VAD，安靜 800 毫秒 | 同一句，同一個地方停一秒 | 你一停，豆豆就搶著回答 |
| 3 | 維持 Server VAD | 「講一個你最喜歡的故事給我聽。」豆豆講到一半時說「等一下」 | 豆豆停下來。是回合偵測中斷豆豆，不是 Prompt 叫豆豆停 |
| 4 | 取消勾選「你一開口，就讓 Dodo 停下正在講的話」 | 同第 3 步 | 豆豆不停，把話講完 |
| 5 | 改回 Push-to-talk | 按著畫面上的按鈕講，講完放開 | 放開才送出；鄰座再吵也不會觸發豆豆 |

**教室的噪音就是教材。** 第 1、2 步常會看到豆豆在你沒講話時自己開始回答：那是鄰座的聲音被當成你在講話。講師直接點出來：這就是 Push-to-talk 存在的理由，第 5 步做完大家會聽到差別。

## 講師示範：Prompt 是拜託，不是保證（145–155 分）

講師一個人做，學生看投影：

1. 在「對話方式」分塊最後加一句「一次最多兩個短句」，按「套用」。
2. 打同一句話連問五次，例如「今天天氣好冷，你覺得我要穿什麼？」
3. 數五次裡有幾次真的只講兩句。

長度寫在 Prompt 裡，模型會盡量配合，但沒有任何機制保證每一次都照做。對照實作三第 3 步：插話時豆豆會停，是因為回合偵測一聽到你開口就中斷豆豆，不靠模型配合。

帶到第二堂的一句話：**哪些事拜託模型，哪些事寫進程式。** 第二堂「什麼時候必須閉嘴」全部寫在程式裡，理由就是這五次。

課前先在講師機試一次。當場五次都照做也照實講：這一次剛好都照做，不代表下一次也會；插話停下則不看模型願不願意。

## 完成標準

看學生做了什麼，不逐一口頭檢查：

- 打字和語音的回答都來自真正的 OpenAI Realtime API，不是本機寫死的罐頭回應，也不是另外接的文字模型。
- 問「你叫什麼？我叫什麼？」時，豆豆答得出「角色與身分」分塊裡的名字和稱呼。
- 改過至少一個 A 區分塊並按過「套用」，用同一句話比過前後的回答。
- 有耳機的人：做過實作二，聽過同一句話換演法、換聲線的差別。
- 有耳麥的人：跟著全班做完實作三的五步，至少聽過一次搶話和一次插話被停下。
