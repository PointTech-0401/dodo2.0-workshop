# Workshop 1：讓 Dodo 聽完，再回答

主題：把一個會講話的 AI 拆成三件事：講什麼、什麼時候換人講、一次講多長

時間：165 分鐘

## 這堂課真正要教什麼

會講話的 AI 不是「Prompt 多寫幾句」就會變自然。學生要分清楚三件事，每一件在這個專案裡都找得到位置：

| 這一層管什麼 | 白話說 | 在畫面上的哪裡 |
|---|---|---|
| Model instructions（Prompt） | 它是誰、講話什麼口氣、能講什麼不能講什麼 | 右邊 A 區那五個分塊 |
| Turn detection（回合控制） | 什麼時候開始聽、怎麼判斷你講完了、你插話算不算數 | 右邊 B 區 |
| Output length（長度） | 一次回答多長 | A 區的「對話方式」分塊 |

**「最多講兩句」只能用寫的，不能用鎖的。** Prompt 裡可以叫它講短一點，但模型不保證每次都照做。那為什麼不設字數上限？因為上限一到就硬切，句子會斷在一半。正式 dodo 因此不設字數上限，這個專案跟著做：長度用 Prompt 描述，不用程式砍。

**「安靜多久算講完」只有用麥克風講話時才有意義。** 打字按送出不會經過這一關。

**Prompt 是什麼時候送出去的？** 一連上線就跟著送出去，所以豆豆的第一句話就已經是你設定的角色；按「套用」會再送一次更新。若不在連線時送、只靠事後補送，第一個回合會落在 OpenAI 的預設人格上，你會看到豆豆用英文回答。

## 學習成果

- 講得出 Prompt、VAD（讓程式判斷你講完了沒）、Push-to-talk 各自負責什麼，以及為什麼長度交給 Prompt，而不是設硬上限。
- 用真正的 OpenAI Realtime API，比較改了不同分塊之後回答有什麼不一樣。
- 比較三種「怎麼判斷你講完了」的方式：Server VAD、Semantic VAD、Push-to-talk。
- 按「套用」把設定真的送進正在進行的對話，再用同一句話比前後差別。
- 把這一堂的成果存成一個檔案，第二堂接著用。

## 開始前：先接上真的模型

第一次啟動時，畫面上會分別要你填 OpenAI 的 Key 和天氣的 Key。每個 Key 旁邊只有一顆「測試」，它只確認這把 Key 有沒有效；真正存下來靠畫面最下面那顆按鈕。沒測過的 Key 會在存之前自動測一次。

設定完之後，右上角「系統設定」還可以再打開；視窗右上角有「×」（按 Esc 也行），關掉會丟掉還沒存的東西。

Key 只送到這台電腦上的程式裡，跟著程式一起活著，程式一關就沒了；不會存進瀏覽器、不會寫進你下載的作品檔、也不會出現在網頁程式裡。講師也可以事先幫每台電腦設好。天氣 Key 沒填一樣可以上課，只是問天氣時它會明講「還沒設定」。

沒填 OpenAI Key 時聊天會直接停用，不會拿罐頭句子假裝自己是模型。

## 實作一：Prompt 只改變「它怎麼回答」

1. 選「打字輸入／文字輸出」，確認標題下面寫著「Realtime 已連線」（沒連上會寫「尚未連接 Realtime」）。
2. 先問「你叫什麼？我叫什麼？」，確認 Prompt 裡的名字和稱呼生效了。
3. 用預設的 Prompt，輸入：「我今天第一次自己搭公車去醫院，有點緊張。」
4. 也可以先按「快速套用範例人格」的三個範例（溫柔陪伴／神經模式／啦啦隊長）聽差別。它們會換掉 5 個分塊和聲線，但你取的名字和稱呼會留著。
5. 挑一個分塊改。例如把「個性與聲音」改成講多快、聲音高低、什麼態度這類聽得出來的事，或改「對話方式」裡追問的規矩；改的同時，下面那份完整 Prompt 會馬上跟著變。
6. 按標題列右邊的「套用」，再輸入**一模一樣**的那句話。那顆按鈕只有在你改過、而且還沒送出時才會出現。看不到它，就代表模型收到的已經是畫面上這一份。下面那份完整 Prompt 只能看不能改，要改就回上面的分塊。
7. 比較內容、口氣和長度。**不要**把打字回答的快慢當成 VAD 的效果，那是兩回事。
8. 在「對話方式」分塊裡改長度規則（例如「一次最多兩個短句」對比「可以講長一點」），再比一次回答長度，這是用寫的請它配合，不是程式硬砍。

這個專案用的模型、逐字稿模型、收音降噪設定和預設聲線（`sage`），都跟正式 dodo 一樣。預設的 Prompt 也對齊正式版：虛擬孫女、臺灣繁體中文、講話慢一點、溫暖一點。

**聲線和 Prompt 是兩件事。** A 區的「Dodo 的聲線」決定音色（10 種可以挑），「個性與聲音」分塊決定用字、節奏和態度。改分塊不會換成另一個人的聲音；改聲線也不會讓它變得比較有耐心。程式不會偷偷從你寫的形容詞裡去猜語速。

**同一段對話中途不能換聲音**，這是 OpenAI 的規定。改了聲線按「套用」，畫面會自己斷線重接。這件事值得在課堂上討論：一個 API 的限制，怎麼變成使用者看得到的行為。

**那句「我幫您看一下」是什麼？** 預設的「對話方式」分塊要求豆豆在查天氣或讀寫記憶之前，先講一句說明自己要做什麼，例如「我幫您看一下臺北現在的天氣」。這句在畫面上標成 `DODO · PREAMBLE（工具前的開場）`，用虛線框起來，跟正式回答分開。

可以請學生把那句要求從分塊裡刪掉再按「套用」，比較有沒有這句開場的差別。

> **實作備註（給維護的人）**：Realtime API 沒有 preamble 這種東西，客端是靠結構認出來的：同一個 `response` 裡同時出現 message 和 function_call，那個 message 就是 preamble；工具結果送回去之後建立的下一個 `response` 才是正式回答。

## 實作二：真正的回合控制

右邊 B 區改的東西，會直接送進正在進行的那段對話：

- **Semantic VAD（等待傾向 low）**：聽你話的意思判斷你講完了沒。適合講話慢、句子中間會停頓的人。
- **Server VAD（安靜 800 毫秒）**：你安靜夠久就算講完。最容易直接看出「反應快」和「被搶話」之間的拉扯。
- **Push-to-talk**：完全不猜，按著講、放開才送出。吵雜教室裡最穩。
- **你一開口就讓它停下來**：你插話時中斷它正在講的那句。Push-to-talk 模式下靠取消目前這一輪做到。

沒有耳麥的學生改完設定按「套用」，用同一句話比回答的差別就好。有耳麥的學生把輸入改成語音後，畫面會自動重新連線，接著照順序試：

1. 講到一半停半秒，再繼續講。
2. 一句話講完，等它回答。
3. 它正在回答時你再開口。
4. 換成 Push-to-talk，確認只有放開按鈕才會送出去。

## 完成標準

- 打字和語音的回答都來自真正的 OpenAI Realtime API，不是本機寫死的罐頭回應，也不是另外接的文字模型。
- 問「你叫什麼？我叫什麼？」時，它答得出「角色與身分」分塊裡的名字和稱呼。
- 學生講得出：A 區是 Prompt（它是誰、什麼口氣、講多長都寫在這裡），B 區是「什麼時候算你講完了」。
- 按過「套用」。
- 下載的作品檔裡有這一堂的設定，而且**沒有**任何 API Key。
