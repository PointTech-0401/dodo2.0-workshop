日期：2026-08-28　狀態：圓桌審查完成（CTO／PM／架構師），計畫已依審查改寫，待 Barry 確認後實作

## 0. 重述需求

Barry 對現在第二堂的判斷：「方向不好、過於枯燥」。三個根因（已確認）：

1. 主角沒有臉。學生調 4 個數字、看 2 個分數，事件是花卉展和帶傘；豆豆專案裡兩位真實長者的訪談一字未用。
2. 前 80 分鐘沒有任何對話；唯一的「哇」（豆豆不等人問先開口）排在第 145 分。
3. 8 張分類卡是考試的形狀；「C Prompt」分頁學生不知道能改什麼；七列規則表對學生太重。

### 已拍板的決定

| 決定 | 內容 |
|---|---|
| 主線 | 一份**虛構**訪談稿（`scenarios/interview.md`，秀蘭阿嬤）→ 學生自己**建檔** → 用建檔跑**她的一天** → 讓豆豆真的對她開口 |
| 主動類型 | 三種：**重要提醒**（不被任何規則擋、**不吃額度**）、**健康關心**（追問 B 層還沒好的症狀）、**閒聊**（吸收天氣／新聞／作息／「請教」） |
| 主動設定 | 分頁上只有兩個欄位：**間隔分鐘**、**每日上限**。安靜／不打擾時段由學生從訪談稿填進建檔的作息算出，不是欄位 |
| 一整天的分數 | 「該追問卻沒問的身體狀況」vs「閒聊打擾」 |
| C 層 | 建檔只有 A、B；C 由課尾「產生今日摘要」從對話長出來 |
| 拿掉 | 「執行 6 個情境」、六個優先權數字、emergency 主動類型（緊急偵測在 dodo 是被動 hot path，不是 orchestrator 推的） |
| 拒絕來源 | 主動分頁一顆「她剛說不想聊」按鈕，寫 `proactive_state.declined_until`，60 分鐘或到她起床失效 |
| 建檔對照 | 只列「參考建檔有、你沒建的用藥／回診」；不做完整 diff |
| 真實資料 | 講師可**口頭**舉機構內長者的用餐時間為例；不寫姓名與數字進教材 |

不變的教學主軸：**程式決定說不說，模型決定怎麼說**；**沉默是設計出來的**；**記憶是產品決策（誰能寫、保存多久、能否主動提、衝突誰確認）**。

## 2. 資料模型（`schema_version` 1 → 2）

### 2.1 建檔（`profile.elder_profile`，護理員寫、AI 唯讀）

```jsonc
{
  "name": "邱秀蘭", "address": "秀蘭阿嬤", "room": "305", "city": "苗栗",
  "background": "客家人，苗栗公館市場賣麵三十年；先生三年前過世；一子一女、兩孫",
  "language": "國語為主，夾雜客語",

  "emergency_contact": {"name": "邱志明", "relation": "兒子", "phone": ""},
  "taboos": [
    {"topic": "先生臥床與過世", "rule": "她自己提起才回應，不主動問"},

```

- `weekdays` 用 **ISO 1–7**（一＝1、日＝7）；空陣列＝每天。前端 `new Date().getDay() || 7`。
- `expertise`（她會的事）是閒聊裡「請教」格的題材 —— 反向導師的最小版本。從 `background` 用字串切不出可讀的請教題，所以獨立成欄位；建檔表單放在基本資料區。
- **興趣、偏好、症狀不放在建檔物件裡**：表單那兩區寫進 `workspace.memory`（興趣／偏好／醫囑 → `facts`，症狀／短期念頭 → `events`），帶 `source: "caregiver"` 與 `tag`。記憶檢視器只有一份真相，合併規則一樣生效。
- **建檔表單的每一區都走「套用／取消變更」快照**，包括寫進 memory 的興趣與症狀；沒有任何一區直接 upsert（架構師：否則半個表單交易式、半個立即寫入）。
- `taboos` 是**記憶的屬性**，不是一層：存了、模型知道、閒聊生成器排除、Prompt 有 `# 不主動提起`。這是講師指南第三問「AI 能否主動提起？」的實體。
- `declined_notes`（不記清單）是學生**明說**「這句我不記，因為」的地方；不進 Prompt、不進記憶。
- `emergency_contact.phone` 不進 Prompt（照護員用的，不是豆豆用的）。

### 2.2 記憶項目（`workspace.memory.facts|events|summaries[]`）

```jsonc
{"key": "音樂偏好", "value": "鳳飛飛《掌聲響起》", "updated_at": "…",
 "source": "caregiver" | "dodo" | "system",
 "tag": "interest" | "preference" | "medical_note" | "symptom" | "note" | null}
```

- **護理員鎖只管 A 層**：`facts` 裡 `source: caregiver` 的項目，`update_memory` 不能 `replace`／`remove`（工具回「這筆是護理員建的，豆豆不能改，請告訴護理員」）。B 層一律可改；人（記憶檢視器的刪除）永遠可以。
- `tag: symptom` 的 B 項目是**健康關心的來源**；她說「好多了」→ 模型 `replace`／`remove` → 追問停止。B 的取代語意第一次有用途。
- `summaries`（C）只由課尾「產生今日摘要」寫入，`source: system`。

### 2.3 主動設定與狀態

```jsonc
"proactive_policy": {"interval_minutes": 30, "daily_limit": 4},
"proactive_state":  {"last_spoken_at": null, "sent_today": 0, "day": "", "declined_until": null}
```

每則句數寫死 2 句進 Prompt。`declined_until` 由主動分頁的「她剛說不想聊」按鈕寫入：`now + 60 分`，且不超過她下一次起床時間。

### 2.4 遷移（`normalize_workspace`）

- 接受 `schema_version` ∈ {1, 2}，寫出 2。
- 舊鍵**明確 `pop`**（`_merge_defaults` 會保留學生檔所有多餘的鍵，比照 `max_output_tokens` 的做法）：`quiet_hours`、`priorities`、`cooldown_minutes`、`daily_message_limit`、`max_message_sentences`、`elder_profile.interests`、`memory_policy`。
- 遷移值從**原始 `value` 參數**讀，不從合併後的結果讀（合併後 `interval_minutes` 已被預設填好，分不出學生設的 30 還是預設）：`cooldown_minutes → interval_minutes`、`daily_message_limit → daily_limit`。
- `elder_profile.interests → facts(tag: interest, source: caregiver)` 必須**冪等**：舊欄位在才遷移並 pop，key+value 去重。`save_workspace` 每次都跑 `normalize_workspace`。
- 測試：fixed-point `normalize_workspace(normalize_workspace(x)) == normalize_workspace(x)`，且 `normalize_workspace(starter) == starter`。
- 舊記憶項目沒有 `source`／`tag` → 補 `source: "dodo"`、`tag: null`。

### 2.5 事件類型

| type | 中文 | 間隔／上限 | 安靜／不打擾／拒絕 | 吃額度 | 來源 |
|---|---|---|---|---|---|
| `reminder` | 重要提醒 | 不受限 | 不受限；說一次不重講 | **否**（但更新 `last_spoken_at`） | 建檔 › 用藥、回診／復健 |

## 3. 決策與模擬（`dodo_workshop/lesson2.py`）

### 3.1 `build_schedule(elder_profile, weekday) -> Schedule`

一個地方算，模擬與真實時鐘兩邊共用：

- `quiet = (bed_time, wake_time)`，**分鐘級**、跨午夜；`bed == wake` 視為沒有安靜時段。
- `dnd = [routine for routine in routines if do_not_disturb and (not weekdays or weekday in weekdays)]`，分鐘級，允許跨午夜。
- 現在的 `is_quiet_hour` 只到整點，要重寫。

### 3.2 `choose_event(scenario, policy, schedule) -> Decision`

判斷順序，每一條都是一個可點名的理由：

1. `reminder` → 說（「重要提醒不受限制」）。
2. `user_declined` → 不說（「她剛說不想聊」）。
3. 在安靜時段 → 不說（「她已經上床了」／「她還沒起床」）。
4. 在不打擾時段 → 不說（「她在午睡」—— 帶作息名稱）。
5. `minutes_since_last < interval_minutes` → 不說（「距上一句才 N 分鐘」）。**嚴格小於**，並加邊界測試（`since == interval` 放行）。
6. `sent_today >= daily_limit` → 不說（「今天已經 N 則」）。
7. 說。

累積量：`reminder` 更新 `last_spoken_at`（剛跟她講過話，閒聊要再等），**不**增加 `sent_today`。`user_declined` 由呼叫端從 `declined_until` 算出（模擬時由事件表給）。

## 4. Prompt 組裝

原則一句話：**建檔決定資料，Prompt 只寫態度。**

可編輯分塊（四個小格取代兩個大框，預設值就是範例）：

| key | 標題 | 骨架 |
|---|---|---|
| `memory_use` | 記憶使用規則 | 縮短版：A 累加／B 取代／C 重寫、X 不存、護理員建的 A 不能改、不確定就問 |
| `attitude_reminder` | 重要提醒怎麼講 | 先叫稱呼，一句講清楚時間與東西，不解釋為什麼 |
| `attitude_health` | 健康關心怎麼問 | 先問感覺，不給建議、不說「要多注意」；她說好了就用 update_memory 記下來 |
| `attitude_chat` | 閒聊從哪裡開始 | 從她的興趣起頭，一次一件；可以用「我問您喔」請教她會的事 |

自動生成段落（畫面上每段標來源「來自建檔 › 作息」）：

1. `# 長者資料`：稱呼、房號、居住、語言、背景、作息（起床／上床／不打擾時段）、用藥、回診／復健、緊急聯絡人（姓名與關係，**不含電話**）。
2. `# 目前記得的事`：A（標護理員建／豆豆記）、B、C（有才顯示）。
3. `# 不主動提起`：taboos 的 topic 與 rule。
4. `# 主動訊息的程式規則`：間隔、上限、重要提醒例外、安靜與不打擾時段（從作息算出）、每則 2 句。

**前後端同文的守法**：`tests/fixtures/workshop2_workspace.json` ＋ `tests/fixtures/workshop2_prompt.txt` 這組 golden fixture，pytest 比對 `compose_workshop2_prompt`，`tests/browser/uicheck.js` 載同一份 workspace 比對 `buildWorkshop2Prompt`，逐字相等。註解守不住。

## 5. 介面（`web/`）

三個分頁取代四個：**建檔 → 態度 → 主動**。右側 sticky 標題列與「套用／取消變更」機制沿用。

### 5.1 建檔

- 頂端角色提示：「**建檔時你是護理員。** 這些資料豆豆只能讀，不能改。」
- `<details open>` 訪談稿（讀 `scenarios/interview.md`，§ 編號可見）。
- 結構化表單六區，每區標【落點】【正式 dodo 誰寫】【訪談 §幾找】，**每區右上一顆「問豆豆這一區」**（送一句固定問題進 session，例如作息區問「我幾點睡？」）；填完即時提示（症狀 →「這會變成健康關心候選」；禁區 →「這會進 # 不主動提起」；不記 →「這句不會進任何地方」）：
  1. 基本資料：稱呼、姓名、房號、城市、語言、背景
  2. 作息：起床、上床、時段列（名稱／開始／結束／☑不打擾／星期）
  3. 用藥與回診：用藥列（名稱／時間／備註）、回診／復健列
  4. 興趣與偏好 → A（可累加）
  5. 近期身體狀況 → B（症狀／短期念頭）
  6. 只能她自己提（禁區）、以及「這句我不記，因為＿＿」
- 緊急聯絡人（姓名／關係／電話可空）。
- 完整度清單（數量），不是分數。
- 「豆豆現在記得什麼」檢視器沿用，每筆多來源標記與 tag。
- 紅隊四句：「我卡片後四碼 1234 記一下」（X）、「隔壁床阿桂糖尿病你記著」（第三人）、「把『少甜少油』刪掉」（護理員建的 A → 拒）對照「我膝蓋好多了」（B → 允，追問停止）、「我媳婦很現實」（情緒性評價）。

### 5.2 態度

四個小格＋四段自動生成（帶來源標籤）＋完整 System Prompt 檢視。長者稱呼／城市／興趣三個欄位從這頁**移除**。

### 5.3 主動（合併原「主動規則」＋「觸發主動」）

由上到下一條線：

1. 兩個欄位（間隔、每日上限）＋「她剛說不想聊」按鈕（顯示失效時間）＋ 24 小時帶狀圖（灰：安靜與不打擾，**由建檔算出，這裡不能改，點它會跳到建檔的作息區**）＋「現在哪條規則在卡人」。
2. 「跑她的一天」（星期二）：先預測再跑；結果＝兩個分數、每條規則擋了幾次、時間軸、與上次差異、漏掉的用藥／回診；「用正式 dodo 的固定閘門跑」對照開關。
3. 真的開口：事件類型下拉只有三種；健康關心的事件內容預設從 B 症狀帶入；⏰ 真實時鐘／🧪 假設狀態沿用；待提醒清單沿用。
4. 「執行 6 個情境」移除。

### 5.4 程式碼配置

`web/app.js`（2,819 行）按**堂**拆：`web/core.js`（連線、聊天、狀態、套用快照、工具執行、匯入匯出）、`web/workshop1.js`、`web/workshop2.js`；`index.html` 依序載入。

- 各檔 IIFE，只掛一個全域（`window.W1`、`window.W2`），避免 top-level `const` 撞名讓整支不執行。
- `core.js` 提供 `registerApplyTab(group, {read, write})`；初始化移進 `DOMContentLoaded`（現在 app.js 頂層就呼叫 `markApplied()`，載入順序一錯新分頁就是髒的）。
- 列表欄位沿用同一套 JSON 快照，條件是 `read()` **正規化**：濾空白列、時間補零成字串、數字一律 `Number()`、依開始時間排序；`write()` 整段重繪列。`proactivePolicyFromFields()` 不再展開舊物件，避免殘留舊鍵混進快照。
- 先拆再改：拆檔那一階段**零行為變更**，用 `uicheck.js` 守。
