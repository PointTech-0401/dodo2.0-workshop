# Workshop 2：會記得、會主動，也知道何時閉嘴

主題：dodo 三層記憶、Proactive Agent 與安全界線

時間：165 分鐘

## 學習成果

- 區分重要事實、近期事件、跨日摘要與不應保存的資料。
- 解釋為什麼主動 Agent 需要規則，而不能只靠模型自由決定。
- 設計安靜時段、冷卻時間、每日上限與事件優先權。
- 使用情境測試檢查 Agent 是否過度打擾或漏掉緊急事件。

## 時間表

| 時間 | 內容 |
|---|---|
| 0–15 分 | 載入第一堂作品；只參加第二堂者載入 starter |
| 15–35 分 | Layer A、B、C 三層記憶 |
| 35–55 分 | 主動事件：提醒、健康、天氣、新聞、反向導師 |
| 55–70 分 | 安靜時段、冷卻、預算與緊急事件優先權 |
| 70–80 分 | 休息 |
| 80–105 分 | 實作一：8 題記憶分類挑戰 |
| 105–145 分 | 實作二：修改主動策略並跑 6 個情境 |
| 145–165 分 | 安全界線驗證、完成 6/6、下載升級後作品 |

## 實作一

啟動共用客端並切到 Workshop 2：

```powershell
uv run python app.py
```

學生必須為每張資訊卡選擇 A、B、C 或 X，畫面立即顯示分數。老師依序說明：

- 誰能寫入或修改？
- 保存多久？
- AI 能否主動提起？
- 發生衝突時由誰確認？

## 實作二

1. 在右側設定區保存預設規則，執行 6 個固定情境。
2. 修改安靜時段、冷卻時間或每日上限。
3. 再次執行，直接比較哪些情境改變。
4. 恢復安全預設，使 6/6 通過。

學生至少調整兩項：

- quiet hours
- cooldown minutes
- daily message limit
- event priorities

## 講師安全示範

- 把 emergency 的優先權調低，會發生什麼？
- 使用者拒絕聊天是否應擋住吃藥提醒？
- 半夜的一般健康關心應不應主動開口？
- 如果同時有回診提醒和新聞，只能說一件事時應選哪個？
- AI 是否能因「最近心情低落」就自行通知家屬？

最後由講師恢復 starter 的安全預設，讓學生看到「模型負責措辭，程式規則負責是否執行」的差異。完成記憶分類與 6/6 情境後，下載升級後的 `my-dodo.json`。
