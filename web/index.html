實作二：她的一天

          
程式決定說不說，模型只決定怎麼說。下表就是那套程式規則的全部內容，按 choose_event() 的判斷順序排。中間那一欄是它存在的理由——拿掉它，下面「跑她的一天」裡就真的會發生那件事。

          

            為什麼會主動說話的 Agent 一定要有規則？
            

              
最大的風險不是講錯，是在不該講的時候講：她還沒起床、她剛說不想聊、五分鐘前才講過、今天已經煩她四次。

              
而且這幾條不能只寫在 Prompt 裡拜託模型自律——模型可以不聽 Prompt，但過不了程式。所以它們寫在 dodo_workshop/proactive.py 的 choose_event() 裡，判斷順序就是下表的順序。

            

          


          
一、你只有兩個旋鈕

          
七條規則裡，只有兩條是數字讓你調。安靜與不打擾由建檔的作息算出來，不在這裡改——因為那是她的生活，不是設定值。

二、跑她的一天（星期二）

          
用你這兩個數字，把她星期二的事件從頭走到尾。回報兩個互相拉扯的數字：漏掉的健康關心與打擾。沒有滿分答案。

          

            為什麼要先猜再跑
            

              
先寫下你猜的數字，再按下去。猜錯的地方就是你對這套規則的誤解——直接看結果很容易變成「哦，原來是這樣」，猜過再看才會記得為什麼。

              
而且一整天不是六個獨立情境：間隔與每日額度會累積下去，早上多聊一句，晚上的睡前提醒就少一次額度。

三、真的開口

          
這裡是唯一會讓豆豆真的在聊天室先開口的地方。同一套 choose_event 先判斷，通過才送 response.create 讓它說話，被擋下來就只顯示理由。

          

            先講清楚這裡「沒有」什麼
            

              
沒有排程器：真實的 dodo 由事件源在背後推事件，這裡由你排一筆待提醒代替它。

              
事件類型沒有串接任何資料來源，它只做兩件事——決定要不要吃額度、以「事件類型：X」寫進這一輪的 Prompt。要說什麼完全來自你填的「事件內容」。
